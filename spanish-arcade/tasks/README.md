# Tasks

Work on Spanish Arcade is split into task files so different chats (and models) can take them in parallel. One file per task: `NNN-name.md`.

How the board works (claiming, statuses, model choice, coordinator runs): [`task-board` skill](../../.claude/skills/task-board/SKILL.md) and [AGENTS.md](../../AGENTS.md).

## How to take a task
- **One task per chat:** open a chat on the keymon-labs project with the task's **recommended model** and say *"Do task spanish-arcade/tasks/NNN-name.md"*.
- **Coordinator:** open one chat (Sonnet) and say *"Coordinate spanish-arcade/tasks"* (optionally *"…up to 3 tasks"*). It works through ready tasks, handing bigger or parallel ones to subagents on each task's model ([AGENTS.md](../../AGENTS.md#board-runs-light)).
- Either way: the standard preamble below, then the task's `Prompt`; `status: in-progress` + `claimed:` pushed at the start, `status: done` (or `review`) in the same commit as the work. `npm run tasks` regenerates the table below and lists what is ready.

## Task file format
```markdown
---
id: "006"
title: …
model: Sonnet 5.5          # recommended; why in one line
why_model: …
status: todo               # todo | in-progress | review | blocked | done  (`review` = waiting for the owner, e.g. a Spanish check; only the owner sets `done` for content tasks)
claimed: 2026-11-07        # set with in-progress; `npm run tasks` flags claims older than 3 days
depends_on: ["001"]
touches: [paths this task creates/edits, so parallel chats avoid clashes]
---
## Prompt           self-contained instructions
## Acceptance       checkable bullets
## Notes            risks, decisions, follow-ups
```
If a task finds a plan problem, it fixes `docs/PLAN.md` in the same commit (contracts changes: say so in the commit message) and notes it under `Notes`.

## Standard preamble (every task)
- `git pull`. Read [CLAUDE.md](../../CLAUDE.md), then [docs/PLAN.md](../docs/PLAN.md), then only the docs the task points to. Don't read the whole tree. The book is not in this repo and not needed: [docs/BOOK-NOTES.md](../docs/BOOK-NOTES.md) is the digest.
- **Reference material** for content tasks lives in the separate `private-assets` repo; clone it beside this one (`../private-assets`) and use it as source. Only our own notes and original content come back here.
- **Public repo.** No personal data anywhere: tests, fixtures and examples use invented profiles ("Test Child", "Class X"). No text, images or audio copied from the book; the cast appears only as our own drawings; write original content on the same topics. No `Claude-Session:` lines or private links in commits.
- Stay inside the task's `touches`. If you need another area changed, do the minimal change and say so in `Notes`.
- Follow the `labs-apps` skill for checks: `npm test`, `npm run build`, headless Chromium check of changed pages, then commit and push to `main`.
- Reply with one line on what changed and one on anything skipped.
